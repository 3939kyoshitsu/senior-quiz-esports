# シニア向け e-スポーツクイズ（試作版 v0.1）

10月14日の本番に向けた、最小の試作版です。参加者はスマホのブラウザから参加し、
進行役が問題を進め、大画面にランキングや正解を表示します。

## できること（試作版の範囲）
- QRコード／参加コードでの参加、ニックネーム・チーム登録
- 4択クイズの出題・回答・自動採点（正解1,000点＋スピードボーナス最大200点）
- 個人ランキング・チームランキングのリアルタイム表示
- 3部門の表彰（優勝チーム／最速回答チーム／わきあいあい賞）
- 画面が消えても、開き直せば自動で復帰

**まだ入っていないもの（後日追加予定）**：文字サイズ切替、効果音・BGM、途中参加、
問題の追加・編集画面（今は `questions/sample.json` を直接編集）、記憶クイズの本格演出。

## 1. Firebaseプロジェクトを作る

リアルタイムに得点やランキングを同期するために使います。無料の範囲で今回の規模（25名）は収まる見込みです。

1. https://console.firebase.google.com/ を開き、Googleアカウントでログインします。
2. 「プロジェクトを追加」→ プロジェクト名を入力（例：`senior-quiz-esports`）→ 作成します。
   （Googleアナリティクスは今回オフで大丈夫です）
3. 左メニューの「構築」→「Realtime Database」を開き、「データベースを作成」します。
   - ロケーションは `asia-southeast1`（シンガポール）など、日本から近い場所を選びます。
   - セキュリティルールは、最初は「テストモードで開始」を選んでください（あとで手順4のルールに差し替えます）。
4. 「ルール」タブを開き、このリポジトリの `database.rules.json` の内容を貼り付けて「公開」します。
   （参加者が誰でも読み書きできる、試作版向けの簡易ルールです。本格運用時はさらに絞り込みます）
5. 左メニューの歯車アイコン →「プロジェクトの設定」→ 下の方の「マイアプリ」で「</>（ウェブ）」を選び、
   アプリ名を適当に入力して登録します（Firebase Hostingは使わないので、そのままでOKです）。
6. 表示された `firebaseConfig` の値（apiKey、authDomain など）を、
   `shared/firebase-config.js` の該当箇所に貼り付けます。

## 2. GitHubにアップロードして公開する（GitHub Pages）

1. GitHubで新しいリポジトリを作成します（例：`senior-quiz-esports`、Public）。
2. このフォルダの中身をすべてそのリポジトリにアップロードします。
   - Claude Codeを使う場合は、ターミナルで次のように行えます（リポジトリURLは作成後に表示されるものに置き換えてください）。
     ```
     git init
     git add .
     git commit -m "最小の試作版を追加"
     git branch -M main
     git remote add origin https://github.com/（あなたのアカウント）/senior-quiz-esports.git
     git push -u origin main
     ```
3. GitHubのリポジトリ画面で「Settings」→「Pages」を開き、
   「Branch」を `main` / `/(root)` に設定して保存します。
4. 数分待つと、`https://（あなたのアカウント）.github.io/senior-quiz-esports/` で公開されます。

## 3. 動作確認のやり方

1. 進行役用の画面（`/host/`）をパソコンやタブレットで開き、合言葉を決めて「大会を作成」します。
2. 大画面用の画面（`/screen/?room=参加コード`）をプロジェクターやTVにつないだパソコンで開きます。
3. スマホで参加者用の画面（`/play/`）を開き、参加コードを入力して参加します（QRコードからでもOK）。
4. 進行役画面で「次の問題へ」を押すと、参加者・大画面に問題が表示されます。
5. 参加者が回答したら、進行役画面で「正解を見せる」→「順位を見せる」の順に押します。
6. 全問終わったら「大会を終了」を押すと、3部門の表彰が表示されます。

まずは身近な方3〜4人にお願いして、スマホの回線（Wi-Fiを使わない状態）でも試してみることをおすすめします。

## 4. 問題を差し替えるには

`questions/sample.json` を編集してください。1問ずつ、次の形式で書きます。

```json
{
  "id": "q010",
  "genre": "昭和・平成",
  "level": 1,
  "type": "choice",
  "question": "（問題文）",
  "choices": ["①選択肢1", "②選択肢2", "③選択肢3", "④選択肢4"],
  "answerIndex": 0,
  "explanation": "（正解発表のときに出すひとこと解説）",
  "timeLimit": 20
}
```

先頭に練習問題（`"practice": true`）を1問入れておくと、点数に入れずに操作練習ができます。

現在の `questions/sample.json` には、練習1問＋本番用15問（昭和・平成／歌・芸能／暮らし／大阪府ネタ／日本の雑学）が入っています。進行役は「次の問題へ」を押すたびに、この順番通りに出題されます。

`questions/reserve.json` には、いざという時に差し替えられる予備問題（7問）を用意しています。使い方は、reserveの中から使いたい問題をコピーして、sample.jsonの好きな位置に貼り付けるだけです（reserve.json自体はアプリから読み込まれないので、そのままでは出題されません）。
※ reserve.jsonの中の「記憶クイズ」2問は、大画面に言葉を数秒表示してから消す演出（README内の今後の課題を参照）がまだ実装できていないため、その機能ができるまでは使わないでください。

## 5. 今後の改修候補（試作版を触ってみてからで大丈夫です）
- ホストの合言葉（hostKey）は現状データベース上で誰でも読める状態です。試作段階の割り切りです。実運用前にルールを見直します。
- 途中参加への対応、文字サイズ切替、効果音は要件定義書の優先度Bとして後日追加します。

## 6. 得点・表彰の判定ロジック（v0.2〜）
- 各問題の正解時、参加者ごとに「得点」と「スピードボーナス」を分けて記録しています（`players/{id}/score` と `players/{id}/speedBonusTotal`）。
- **優勝チーム**：チーム得点（全員の平均点）が最も高いチーム。
- **最速回答チーム**：チームのスピードボーナス平均（1人あたり）が最も高いチーム。正解した問題にどれだけ早く反応できたかを表します。
- **わきあいあい賞**：チーム得点の平均が最も低いチーム。
